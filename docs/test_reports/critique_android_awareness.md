## 1. Executive Summary

A comprehensive, zero-assumption systems audit of the Aster Companion Android native implementation was executed against PRD v1.1. The codebase exhibits high-quality architectural scaffolding in several components—including an isolated coroutine-based `ScreenCaptureEngine`, dual-mode audio recording, rolling FPS window math, a hardware-capable AES-256-GCM `KeystoreManager`, and faithful Compose design token implementation across primary screens.

However, the audit uncovered **critical architectural gaps, simulated telemetry that violates core honesty principles, disconnected cryptographic infrastructure, and unverified verification report claims**:

1. **Dead MediaProjection Runtime Path**: While [`MediaProjectionService`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MediaProjectionService.kt#L39) is declared in the manifest, [`MainActivity.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/MainActivity.kt#L41-L65) **never** launches `MediaProjectionManager.createScreenCaptureIntent()`. `MediaProjectionService.startServiceIntent()` is never invoked anywhere in the codebase.
2. **Fabricated Telemetry Loop**: In [`ui/screens/awareness/AwarenessViewModel.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/ui/screens/awareness/AwarenessViewModel.kt#L80-L100), the Compose UI displays **completely synthetic FPS metrics** generated by a random math jitter loop (hardcoding ~60 capture / ~30 upload / ~5 analysis FPS), completely disconnected from [`MetricsTracker`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MetricsTracker.kt#L25) and violating PRD §1.2 Core Principle 10 (Honesty) and §5.3.
3. **Unencrypted Room Outbox Storage**: While [`KeystoreManager.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/data/crypto/KeystoreManager.kt#L58-L250) implements AES-256-GCM, it is **never wired** into [`AsterDatabase`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/data/local/AsterDatabase.kt#L29), [`OutboxDao`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/data/local/OutboxDao.kt#L15), or [`SyncEngine`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/data/sync/SyncEngine.kt#L39). All outbox payloads, chat texts, and screen events are stored in cleartext SQLite. SQLCipher is completely absent from Gradle dependencies.
4. **False Claims in Test Report 25**: [`docs/test_reports/25_android_emulator_e2e_verification.md`](file:///workspaces/codespaces-blank/docs/test_reports/25_android_emulator_e2e_verification.md#L75-L77) certifies that all Android subsystems operate according to specification on an Android 11 emulator, yet the emulator run never tested `MediaProjection`, never prompted for screen capture consent, never acquired a frame, and never displayed the floating pill overlay.
5. **Failing Unit Test Suite**: Executing `./gradlew testDebugUnitTest` reveals that **33 out of 125 tests fail**, primarily due to test coroutine scheduler misuse (`IllegalStateException`) and UI assertion drift.

### 3.1 MediaProjection Foreground Service & Adaptive Sampling

#### A. Manifest and Foreground Service Compliance
- **File**: [`app/src/main/AndroidManifest.xml`](file:///workspaces/codespaces-blank/app/src/main/AndroidManifest.xml#L10-L12)
- **Lines 10–12**: Permissions `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PROJECTION`, `FOREGROUND_SERVICE_MICROPHONE`, and `SYSTEM_ALERT_WINDOW` are declared.
- **Lines 50–55**: Service `MediaProjectionService` is registered with `android:foregroundServiceType="mediaProjection|microphone"` and `android:exported="false"`.
- **File**: [`app/src/main/java/com/astercompanion/android/awareness/MediaProjectionService.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MediaProjectionService.kt#L187-L204)
- **Lines 187–204**: Strictly adheres to Android 14/15 requirements by calling `startForeground()` *before* invoking `mediaProjectionManager.getMediaProjection(resultCode, resultData)`.
- **Lines 218–226**: Registers `MediaProjection.Callback` to handle user/system consent revocation on `onStop()`:
  ```kotlin
  val callback = object : MediaProjection.Callback() {
      override fun onStop() {
          super.onStop()
          Log.w(TAG, "MediaProjection consent revoked by user or system OS callback.")
          handleConsentRevoked()
      }
  }
  ```

#### B. The Missing Runtime Trigger Flow
- **File**: [`app/src/main/java/com/astercompanion/android/MainActivity.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/MainActivity.kt#L41-L65)
- **Lines 41–65**: `requestRequiredPermissions()` only requests `Manifest.permission.POST_NOTIFICATIONS` and `Manifest.permission.RECORD_AUDIO`.
- **Zero Invocations**: A repository-wide search confirms `createScreenCaptureIntent` appears **nowhere** in any executable Kotlin/Java file.
- **Consequence**: In Android, `MediaProjectionManager.getMediaProjection(resultCode, resultData)` requires a valid token obtained via `startActivityForResult(mediaProjectionManager.createScreenCaptureIntent())`. Because the app never launches this system dialog, [`MediaProjectionService.startAwarenessSession`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MediaProjectionService.kt#L156) is unreachable in production.

#### C. Algorithmic Mislabeling in PerceptualDifferencer
- **File**: [`app/src/main/java/com/astercompanion/android/awareness/PerceptualDifferencer.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/PerceptualDifferencer.kt#L108-L123)
- **Lines 108–123**: The function `computePHashFromGrid(grid: FloatArray): Long` calculates:
  ```kotlin
  val avg = sum / 64.0f
  var hash = 0L
  for (i in 0 until 64) {
      if (grid[i] >= avg) {
          hash = hash or (1L shl i)
      }
  }
  return hash
  ```
- **Auditor Critique**: This algorithm is mathematically an **Average Hash (aHash)**, comparing pixel luminance against the arithmetic mean. It is **not** a perceptual hash (pHash, which requires Discrete Cosine Transform / DCT in the frequency domain) and **not** a difference hash (dHash, which compares adjacent horizontal gradients, as correctly implemented in the iOS codebase at [`ios/AsterCompanion/ReplayKit/PerceptualHash.swift`](file:///workspaces/codespaces-blank/ios/AsterCompanion/ReplayKit/PerceptualHash.swift#L31-L85)). While combining aHash with SSIM (lines 136–173) is computationally light for a mobile loop, claiming it is "pHash" in architecture docs is inaccurate.

#### D. Critique of Test Report 25 Claims
- **File**: [`docs/test_reports/25_android_emulator_e2e_verification.md`](file:///workspaces/codespaces-blank/docs/test_reports/25_android_emulator_e2e_verification.md#L51-L63)
- **Lines 51–63**: Section 3.3 documents runtime permission enforcement for `RECORD_AUDIO` and `POST_NOTIFICATIONS`. It records zero interactions with `MediaProjectionManager` or `SYSTEM_ALERT_WINDOW`.
- **Lines 75–77**: The report concludes: *"All core Android subsystems—Compose UI, permissions, Keystore, Room persistence, and background WorkManager—operate according to specification."*
- **Verdict**: **Falsification of Coverage**. The report implies end-to-end verification of Aster's screen awareness capability, when in reality screen capture was never started on the emulator.

### 3.2 Honest FPS and Telemetry Disclosure (0.5 to 2.0 fps) with Floating Privacy Indicator

#### A. Telemetry Fabrication in AwarenessViewModel
- **File**: [`app/src/main/java/com/astercompanion/android/ui/screens/awareness/AwarenessViewModel.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/ui/screens/awareness/AwarenessViewModel.kt#L80-L101)
- **Lines 80–101**:
  ```kotlin
  private fun startTelemetryLoop() {
      telemetryJob?.cancel()
      telemetryJob = viewModelScope.launch {
          while (isActive) {
              delay(1000)
              _uiState.update { current ->
                  if (current.isPaused || current.isStopped) {
                      current
                  } else {
                      val jitter = ((-5..5).random()) * 0.1f
                      current.copy(
                          captureFps = (60.0f + jitter).coerceIn(58f, 62f),
                          uploadFps = (30.0f + jitter * 0.5f).coerceIn(28f, 31f),
                          analysisFps = (5.0f + jitter * 0.1f).coerceIn(4.8f, 5.2f),
                          totalFramesCaptured = current.totalFramesCaptured + 60,
                          monotonicSequenceNumber = current.monotonicSequenceNumber + 60
                      )
                  }
              }
          }
      }
  }
  ```
- **Violations**:
  1. **PRD v1.1 §1.2 Core Principle 10 (Honest operation)**: *"Never claim to have watched, remembered, searched, or executed something that it did not actually process or complete."*
  2. **PRD v1.1 §5.3 (Frame-rate objective)**: *"A capture rate of 120 FPS must never be reported as 120-FPS AI understanding unless the complete processing pipeline has been measured and verified to support that claim."*
  3. **PRD v1.1 §19.2 (Continuous awareness acceptance criteria)**: *"Processing rates are measured rather than assumed... The system does not claim uninterrupted frame-level understanding without supporting evidence."*
  4. **Mobile Power & Thermal Budget**: Running continuous cloud multimodal analysis at 5.0 FPS on a mobile cellular connection is unrealistic and thermally unsustainable; mobile benchmarks specify realistic analysis rates of **0.5 to 2.0 fps**, with upload FPS dropping to **0.1 to 0.5 fps** during static screen reading. The ViewModel instead synthesizes an inflated 60 / 30 / 5 FPS stream using `random()`.
  5. **Total Decoupling from Reality**: The ViewModel ignores [`MediaProjectionService.metrics`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MediaProjectionService.kt#L65) and [`MetricsTracker`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MetricsTracker.kt#L32), generating imaginary frames (`monotonicSequenceNumber + 60`) even when no capture is active.

The repository contains two conflicting ViewModels for awareness:
1. [`app/src/main/java/com/astercompanion/android/viewmodel/AwarenessViewModel.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/viewmodel/AwarenessViewModel.kt#L45): Depends on `CompanionRepository`, sets defaults to `captureFps = 120.0f`, `uploadFps = 30.0f`, `analysisFps = 5.0f`.

Neither ViewModel observes the actual [`ScreenCaptureEngine.frameFlow`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/ScreenCaptureEngine.kt#L53) or [`MetricsTracker.metrics`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/MetricsTracker.kt#L33).

#### C. Floating Overlay Permission Gaps
- **File**: [`app/src/main/java/com/astercompanion/android/awareness/AwarenessFloatingIndicator.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/awareness/AwarenessFloatingIndicator.kt#L131-L134)

#### B. The Missing Encryption-at-Rest Link (CRITICAL GAP)
- **File**: [`app/src/main/java/com/astercompanion/android/data/crypto/KeystoreManager.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/data/crypto/KeystoreManager.kt#L58-L250)

  A global search for `KeystoreManager` confirms it is referenced **only in its own file and its unit test** ([`KeystoreManagerTest.kt`](file:///workspaces/codespaces-blank/app/src/test/java/com/astercompanion/android/data/crypto/KeystoreManagerTest.kt#L11)).

  - [`app/build.gradle.kts`](file:///workspaces/codespaces-blank/app/build.gradle.kts#L124-L129) includes only `androidx.room:room-runtime:2.6.1`. There is **no SQLCipher dependency** (`net.zetetic:android-database-sqlcipher`).

- **Verdict**: Despite PRD v1.1 §16.2 explicitly mandating *"Encryption at rest: Protection against unauthorized access to buffered data,"* **all local data on Android is stored in cleartext SQLite**.

## 4. Auditor Recommendations

### Priority 1: Critical Architectural Repairs
1. **Wire MediaProjection Consent Flow in MainActivity**:
   Add an `ActivityResultLauncher` for `ActivityResultContracts.StartActivityForResult()` in `MainActivity.kt`. When the user enables Continuous Awareness in `AwarenessPanel` or settings, invoke `mediaProjectionManager.createScreenCaptureIntent()` and forward the resulting `resultCode` and `Intent` data to `MediaProjectionService.startServiceIntent(context, resultCode, data)`.
2. **Purge Fake Telemetry Loop**:
   Delete the synthetic random jitter loop in [`ui/screens/awareness/AwarenessViewModel.kt`](file:///workspaces/codespaces-blank/app/src/main/java/com/astercompanion/android/ui/screens/awareness/AwarenessViewModel.kt#L80-L101). Bind the Compose UI directly to `MediaProjectionService.metrics` StateFlow (via `MetricsTracker`). When capture is not active, display `0.0 fps` or an honest `IDLE` state. Restrict maximum analysis rate targets to realistic mobile thresholds (0.5 to 2.0 fps).
3. **Consolidate Awareness ViewModels**:
   Remove the duplicate `AwarenessViewModel` in `viewmodel/AwarenessViewModel.kt` or `ui/screens/awareness/` to establish a single authoritative ViewModel.
4. **Implement Encryption at Rest for Offline Storage**:
   Either:
   - Add SQLCipher (`net.zetetic:android-database-sqlcipher:4.5.4`) to `app/build.gradle.kts` and configure `SupportFactory(keystoreManager.getOrCreateKey().encoded)` on the Room database builder, OR
   - Wire `KeystoreManager` directly into `SyncEngine.enqueueChatMessage()` and `OutboxDao` to encrypt `payloadJson`, `ChatMessageEntity.text`, and `MemoryEntity.title` before SQLite persistence.
5. **Harmonize Design Tokens**:
   Update `AwarenessFloatingIndicator.kt` and `MediaProjectionService.kt` to use the canonical hex codes (`#121110`, `#1C1A18`, `#E59843`, `#7966F3`). Unify `Theme.kt` and `AsterTheme.kt` into a single authoritative design system file.
6. **Fix Unit Test Dispatcher Scheduler**:
   Refactor `setup()` across all ViewModel tests to avoid calling `testScope.runTest` inside `@Before` methods when test methods already invoke `runTest`. Fix the icon resolver matcher in `AsterComponentsTest.kt` and the state transition timing in `VoiceCallViewModelTest.kt`.
7. **Revise Test Report 25**:
   Update `docs/test_reports/25_android_emulator_e2e_verification.md` to truthfully disclose that MediaProjection, live screen capture, and floating overlay were not exercised on the Android 11 ATD emulator.

## 5. Certification Verdict

**VERDICT**: **GAP (FAIL)**

While the UI components and foundational scaffolding reflect high fidelity to PRD v1.1 design tokens and Room DB outbox architecture, the Android Awareness implementation currently fails verification due to:
- A non-functional, uninvoked MediaProjection consent flow.
- Violation of PRD honesty principles via hardcoded fake telemetry jitter.
- Complete absence of encryption at rest for the offline Room outbox and entity database.
- 33 failing tests in the native Android unit test suite.
